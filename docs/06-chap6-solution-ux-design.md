# Capítulo VI: Solution UX Design

## 6.1. Style Guidelines

*Qué debe ir: Establecer un repositorio central y organizado de uso común para assets, fonts y demás elementos necesarios para mantener una presentación consistente y enfocada.*

### 6.1.1. General Style Guidelines

*Qué debe ir: Explicar decisiones y referencias visuales sobre Branding, Typography, Colors y Spacing, además del tono de comunicación y lenguaje (por ejemplo, divertido/serio, formal/casual, respetuoso/irreverente, entusiasta/sereno). Sustentar principios y elementos de diseño y, si corresponde, un Design System de referencia.*

### 6.1.2. Web, Mobile & Devices Style Guidelines

*Qué debe ir: Explicar e ilustrar los estándares visuales y de interacción para interfaces web responsive y aplicaciones móviles nativas. El título oficial también menciona Devices; el enunciado descriptivo desarrolla de forma explícita web y mobile.*

## 6.2. Information Architecture

*Qué debe ir: Explicar las decisiones que dirigen la organización del contenido del Landing Page y las aplicaciones para que los usuarios encuentren lo que necesitan con facilidad. El texto descriptivo menciona Organization, Labeling, Navigation y Searching Systems; la estructura oficial no enumera un 6.2.1 para Organization Systems.*

### 6.2.2. Labeling Systems

*Qué debe ir: Explicar cómo se representarán los datos mediante etiquetas simples y con el mínimo número de palabras, evitando confusión y mostrando las asociaciones entre etiquetas e información.*

### 6.2.3. Searching Systems

*Qué debe ir: Explicar los medios de búsqueda dentro de los productos digitales: opciones disponibles, filtros por caso y forma en que se mostrarán los resultados de búsqueda.*

### 6.2.4. SEO Tags and Meta Tags

*Qué debe ir: Incluir SEO Tags y Meta Tags para las principales páginas del Landing Page y Web Applications: como mínimo Title, Description, Keywords y Author. Para productos expuestos en app stores, el enunciado también solicita ASO elements como App Title, App keywords, App subtitle y App description.*

### 6.2.5. Navigation Systems

*Qué debe ir: Explicar las acciones y técnicas que guiarán a los usuarios a través del Landing Page y las aplicaciones, describiendo cómo recorrerán el contenido para cumplir sus metas.*

## 6.3. Landing Page UI Design

*Qué debe ir: Introducir la propuesta de UI del Landing Page y explicar cómo se traducen las decisiones de diseño y de arquitectura de información.*

### 6.3.1. Landing Page Wireframe

*Qué debe ir: Presentar y explicar los Wireframes del Landing Page para Desktop Web Browser y Mobile Web Browser, evidenciando principios y elementos de diseño, diseño inclusivo y arquitectura de información.*

### 6.3.2. Landing Page Mock-up

*Qué debe ir: Presentar y explicar los Mock-ups del Landing Page para Desktop y Mobile Web Browser, evidenciando principios de diseño, diseño inclusivo, arquitectura de información y el Design System definido.*

## 6.4. Applications UX/UI Design

*Qué debe ir: Presentar y explicar la propuesta visual y de interacción de las aplicaciones que forman parte de la experiencia de usuario.*

### 6.4.1. Applications Wireframes

*Qué debe ir: Presentar y explicar los Wireframes de las aplicaciones, evidenciando principios y elementos de diseño, diseño inclusivo y arquitectura de información, utilizando la herramienta indicada.*

### 6.4.2. Applications Wireflow Diagrams

*Qué debe ir: Elaborar un Wireflow por cada User Goal, considerando los User Persona y cada aplicación del alcance. Puede apoyarse previamente en Task Flows. Cada diagrama debe incluir el User Goal y una explicación del flujo y de los cambios de estado de las pantallas.*

### 6.4.2. Applications Mock-ups

*Qué debe ir: Presentar y explicar los Mock-ups de las aplicaciones, evidenciando principios de diseño, diseño inclusivo, arquitectura de información y el Design System establecido. Se conserva la numeración 6.4.2 porque así aparece en la estructura oficial del enunciado.*

### 6.4.3. Applications User Flow Diagrams

*Qué debe ir: Elaborar un User Flow por cada User Goal y aplicación, consistente con los Wireflows. Incluir Mock-ups, happy path y unhappy paths. Cada diagrama debe indicar el User Goal y explicar los flujos y condiciones.*

## 6.5. Applications Prototyping

*Qué debe ir: Incluir prototipos de UI con simulación de interacción y navegación conforme a los User Flow Diagrams. Explicar criterios de interacción y relación con la arquitectura de información. Para cada aplicación incluir un screenshot y un enlace a un video en Microsoft Stream que demuestre los principales flujos.*
